# 工作台使用说明

适用于 MiniMax H3 视频工作台及共享核心的生图工作台。主面板顶部提供本地/API来源与模型、独立视频/图片LoRA入口、二采和脸修开关；密钥及详细参数在对应折叠区域。工作流打开后定位主工作台，原始节点保留折叠状态。

## 先准备哪几项

| 任务 | 必需 | 可省略 |
| --- | --- | --- |
| 文生视频 | H3主模型、H3专用文本编码器、视频VAE、音频VAE；本地或API文字规划服务 | 图片模型、图片API |
| 一张参考图自动分镜成片 | 上述视频组件、参考图、文字规划；本地图片模型或图片API | 未启用的修复/超分组件 |
| 手工分镜图生视频 | 视频组件、各镜头图片、已确认的分镜计划 | 自动分镜生图模型 |
| 文生图、图生图/分镜修复 | 本地图片模型组合或已配置的图片API | H3视频模型 |

本地文字模型名称以实际模型列表为准。图片模型与H3编码器、VAE不可互换；下载位置与精确文件名见 [MODELS.md](../MODELS.md)。未启用的可选功能不应要求额外下载。

## 文生视频：先规划，也能中途补图

1. 切到“文生视频”，写完整故事。明确人物、场景、事件先后、说话人和原句。选择手动时长或AI分配时长，先生成并检查分镜计划。
2. 在总览核对每镜画面、动作、结束状态和对白。短台词可同属一个镜头，不要为了凑镜头把同一句话拆开。复制/编辑或导入计划后保留计划，再生成视频。
3. 想先手工生图时，在分镜提示词区域复制静态生图提示词。它描述镜头开场，不把整段运动同时塞进一张图片。
4. 将生成好的图片上传到对应镜头，然后继续。该镜自动改用上传图作首帧；其他未填图片的镜头保持原路径。无需在原剧本补写 `@图1`，也不需要重写整份计划。
5. 默认开启文生视频连续衔接：第二镜起可承接上一镜真实末帧，以保持人物与物件。独立场景或需要明确跳切时可关闭。承接后的镜头实际为首帧图生视频，报告会记录真实输入模式。

原稿仍是“文生视频”的任务不等于每一镜必须没有图片；镜头上传图的绑定优先于自动首帧。不要切换整个任务模式来替代单镜换图，否则容易把已有计划视为另一种任务。

## 图生视频：一图自动完成多镜头

1. 上传清晰参考图。多图时，按需要在剧本里引用图号，说明哪张用于人物、服装、场景或物件。
2. 选择“AI生成分镜”，生成计划后先检查；检查分镜图时关闭“生图后生成视频”，确认后打开并续跑。
3. 图片后端可选本地千问或图片API。每镜生成的静帧都使用该镜提示词和绑定参考，前镜的结束状态会参与后镜设计。
4. 不满意的分镜可以单镜编辑、重新生图或上传替换。保留计划与已有任务，继续生成视频；只有受影响的结果应失效。
5. 要严格承接物件位置和动作进度，可选择“上一镜末帧”或“末帧高清续接”；“逐镜参考图”更适合明确的不同构图与切镜。

图生图修复用于准备分镜/末帧图片；视频脸修则处理已经生成的视频帧，两者的模型、LoRA和执行阶段各自独立。

## 提示词怎样更稳定

写清楚“谁在何时做一次什么，做到哪里停止，之后保持什么状态”。例如：

> 咖啡店午后，白衬衫深绿围裙的女店员将透明水杯放在客人面前，说“下午好，请喝水。”说完放松站定。下一镜杯子已在桌面，灰衬衫男客人只轻点一次头，说“谢谢，正好有点渴。”点头结束后保持姿态，自然呼吸和眨眼。

后台会约束说话人、对白顺序、原句与单次手势，并为发音和切镜留出时间。对白多于镜头能容纳的时长会在生成前提示增加时长，不把文字截短。原生模型音频仍需播放验收；要求严格对白可使用独立的对白音轨功能。

尽量不要同一镜同时要求多个剧烈动作、长对白、复杂运镜和道具交接。对白归属明确的两镜各8秒，比一句台词硬塞进不足一秒的窗口更容易检查。

## API设置与密钥

在工作台顶部“模型与API”中，点击语言或图片行右侧的“API 配置”，填写配置名称、接口地址和自己的 API 密钥，再点“保存密钥”；保存成功会明确提示。切到 API 时配置自动展开，并读取该配置可用的模型供下拉选择；失败会显示原因，可点“刷新模型”重试或手动填写模型名称。展开原始语言／图片配置节点时，也可点“API 配置与密钥”打开同一个配置窗口。密码框只用于本机保存，不进入节点控件、工作流或计划JSON。

| 设置 | 作用 |
| --- | --- |
| 文字：本地/API | 剧本与分镜规划；API按选择的模型调用，不回退到本地模型掩盖认证错误 |
| 图片：本地/API | 分镜生图、分镜图编辑和末帧图片修复；无参考时文生图，有参考时图像编辑 |
| 配置名称 | 选择本机保存的独立API配置；文字和图片可使用不同密钥、地址与模型 |
| 模型列表 | 使用当前密钥实际开放的模型；能读取列表不等于已测试生成质量 |
| 分辨率与质量 | 发送给图片服务的真实参数；输出尺寸以服务实际返回为准 |
| 视频API | 预留且禁用，当前视频仍由本地H3生成 |

BBAPI地址可设为 `https://bbapi.ainivox.cn`。价格与分组由账号和密钥决定；工作台不会擅自切换计费分组，也不提供共享密钥。付费生成失败后不自动重提，先查看认证、额度、模型和参考格式的具体错误。

语言模型协议可选“自动”“Responses”或“Chat Completions”。自动对GPT-5/GPT-6/Codex选择Responses，其他模型使用Chat Completions；可按服务能力手动切换。Responses采用`store:false`和有界流读取，只有完整完成且JSON有效才交给分镜规划。认证、502、流中断会保留原稿并明确报错。模型列表可见只能证明能够枚举，仍需当前上游通道支持实际生成。协议格式参考[OpenAI结构输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)。

## LoRA：视频与图片分开

两组都支持添加最多20个槽位，各槽有文件、强度、步数、CFG和启用滑钮，只有启用的非零强度槽位参与当前路线。全部启用LoRA共同作用于模型，再按每槽的步数和CFG依次额外做一轮低降噪细化（降噪0.25）；各槽参数真实送进采样，会增加耗时。旧配置仅有强度时保留原单轮行为，修改步数/CFG或重新启用该槽后采用细化参数。Pika固定六步路线不提供额外槽位细化。

| LoRA类别 | 用在哪里 | 不能混用 |
| --- | --- | --- |
| H3视频LoRA | H3视频模型，例如同架构人物、风格、运镜LoRA | Qwen/Image2.1、SD/SDXL、Flux等图片LoRA |
| Qwen/Image2.1图像LoRA | 本地分镜图片、图片编辑与修复 | H3视频LoRA；其他图像架构的LoRA |
| 加速LoRA | 选定视频路线的配套步数和日程，由加速配置管理 | 不要再作为风格槽叠一次 |

名称筛选只能帮助选择，真实架构仍按权重头校验。未知或不兼容权重应明确报错，不能假加载。API图片生成不会使用本地图片LoRA；请在图片服务自身支持的能力范围内配置。

## 加速、二采与脸修

图片与视频的加速分别配置。主面板“图片”选择真实 `qwen_image_2.1_turbo` 主模型时，首次使用8步；普通版首次25步，两版之后分别记住使用者调整的参数。只修改普通模型的步数不能把它变成 Turbo，视频加速开关也不会改变生图路线。2K原图、多张高分辨率参考会增加每步计算；“480P”等视频档位不限制独立的分镜图长边。可按需要在图像设置中选择1K／2K并确认参考读取长边，不自动缩小原始素材来提速。

加速 LoRA 在采样前作用于主模型，LoRA 强度与这一轮的步数、CFG是不同参数；不会先按普通版跑完，再让加速 LoRA 自己跑另一轮。独立二采和明确启用的 LoRA 细化才是额外采样。本工作台的 Qwen Turbo 使用专用主模型与官方日程，图片版本切换不会影响 H3 视频加速选项。

连续本地 AI 分镜在图片阶段仅复用一套模型、编码器与 VAE，每张图重新编码提示词和参考图，并清理当张前缀缓存。进入视频、图片阶段结束或任务失败时释放权重；开启衔接超分和独立单图生成仍沿用原释放方式。此优化减少重复加载，不降低输出尺寸、参考读取尺寸或采样步数，也不承诺固定生成时间。

| 功能 | 行为 | 起始参数/限制 |
| --- | --- | --- |
| 官方独立加速LoRA | 基础H3搭配专用4/8步权重 | 先用8步检查故事；关闭加速使用基础模型标准采样 |
| 原作者RefDelta融合模型 | 文生、图生与参考音色等路线 | 不叠外置Turbo；已有同款权重可选择，公开模板不强制下载 |
| Pika H3 Flex | 同架构基础模型＋专用FL2VA LoRA | 固定6步、LCM、官方sigma、CFG 1；不可叠Turbo；本版不与二采/裁剪脸修并用 |
| 二次采样 | 对本镜已有视频latent再采一轮精修 | 默认关，4步、去噪0.25；保留原声音；会增加耗时 |
| 视频脸部修复 | 跟踪最大人脸，裁剪后H3再采、颜色匹配和羽化贴回 | 默认关；512画布、8步、去噪0.40、检测阈值0.35、裁剪2.5倍、羽化24px、混合1 |

“视频加速”是固定且不可删除的独立区域，与可增删的视频风格/人物LoRA分开。4步、8步是快捷预设；普通H3可在数字框输入1～100步，实际步数与选择的4步/8步LoRA权重档位分别保存。手动改步数不暗换权重。Pika专用路线采用固定官方六步sigma，显示固定6步。预设之外的步数效果以实际输出为准。

二采不等于普通图片超分；脸修不等于加载一个通用“修脸LoRA”。脸修使用视频H3模型与检测模型，可调整去噪、画布、步数、检测、裁剪及混合。它跟踪一个主体，不保证同时修复多人。没有检测到人脸时保留原帧并记明跳过；缺检测器或依赖时报错，不把未执行显示成已修复。切镜边缘渐变回原帧以减少身份跳变。

本版脸修准备：`ultralytics` Python依赖，`face_yolov8m.pt` 放到 `models/ultralytics/bbox/`。检测器与H3 LoRA是两种不同文件。先检查原片确有小脸问题，再开启脸修；较大画布和二采都会增加时间与内存。

“显存预留GB”默认0自动：Windows低显存模式、显卡不超过20GB时为系统和其他程序至少保留3GB，减少WDDM共享显存换页。也可手动选0～12GB。预算仅在本工具视频执行期间生效，结束或失败后恢复主服务原策略，不修改系统或ComfyUI核心。

Pika模型和固定日程来源见 [ComfyUI官方说明](https://docs.comfy.org/tutorials/video/pika/pika-h3-flex)。本机现有核心的无图条件路径须通过预检，不能只改步数就宣称支持新路线。

## 查看、字幕与继续编辑

分镜和成片分隔线可左右拖动；主工作台四角可缩放，底部高度柄仍可用。默认显示全部分镜；用户主动选择单镜并保存后，才沿用单镜。每个镜头可查看图片、提示词和视频，成片单独预览。

运行中的镜头在预览框显示旋转指示、实际阶段和耗时。主采样、LoRA细化、二采、脸修分别报告当前步骤；有真实采样步数时显示百分比，解码／编码等没有步数的阶段不编造百分比。首轮采样100%之后可能还有二采、脸修、音频解码和视频保存，只有该镜头文件写完才可播放，已完成镜头可先查看。

生成后先逐镜听对白，再检查切镜前后的人物、道具和动作。字幕为独立可选步骤：先识别，检查文本和时间，再导出；改字幕样式不必重新生成视频。字幕不会自动证明模型原音频说对了台词。

关闭界面后保留任务文件和结果；重新打开恢复任务，按原任务续跑。生成失败先看具体镜头错误，保留已成功镜头，不必删除整个任务目录。

## 拖入图片与修复引用

将资源管理器的图片拖到“参考图”区域，可直接加入参考图；拖到分镜图片槽可替换对应镜头。放到画布空白处仍使用资源管理器原来的加载节点功能。取消拖拽、移出窗口或按 Esc 后，拖放提示会清除。剧本中连续点击“未引用”可逐个选择参考图，无需先点击画布。

已安装 Majoor 2.4.9 本地改版时，需要同时更新本发行版附带的 `ComfyUI-Majoor-AssetsManager-drag-compat-v1.3.6.zip`。兼容包只包含前端产物、对应拖放源码和许可证；覆盖同名插件文件后刷新页面，保留用户数据和索引。仅更新 H3 无法修改旧版资源管理器提前截获拖放事件的行为。安装智能体应同时检查两边，并验证参考图数量增加而画布没有新增加载节点。

## 对白复核

模型原生音频仍可能出现多说、漏说或发音不清。工作台保留官方说话人编号，并明确指定对白前后的安静时段；保留计划续跑时会刷新编译规则，保留已确认图片和手工提示词。

每镜原生音频生成后，工作台使用本机 SenseVoice 在 CPU 上对照指定原句，阶段栏显示“复核对白”。识别不一致时显示“对白待复核”，鼠标停在状态上可查看原句与识别结果；识别模型不可用时显示“对白未复核”，不会假报通过。首次加载识别模型会多用几秒，后续复用同一 CPU 会话。语音识别会误认短句，提示需播放确认；识别一致也不代表口型、音色或听感已验收。

复核保留原片和原音轨，不自动剪音、替换配音或反复重跑视频。显式静音和使用者提供的对白音轨跳过此项。本地缺少识别模型时，可按安装说明使用 `--with-speech` 准备；不会在生成过程中自动下载。需要更严格控制声音时，使用已有的对白音轨输入，并播放确认口型。

## 给安装智能体

读取 [AGENT_INSTALL.md](../AGENT_INSTALL.md) 与模型表，识别当前实例的核心、Python、base、user、模型目录，再安装共享核心一次。API密钥由使用者在本机配置；不复制作者的user目录。仅安装启用能力的依赖，保留可工作的PyTorch和既有工作流。

最低验收需覆盖：无缺失节点、主工作台定位、模型枚举、文字规划、分镜提示词复制/图片上传绑定、选择的本地或API生图、视频生成、成片保存、关闭重开恢复。只验证静态schema不能写成视频质量通过。真实推理和付费调用按使用者授权执行，报告实际分辨率、步数、镜头、耗时、音轨/字幕及未通过项。
